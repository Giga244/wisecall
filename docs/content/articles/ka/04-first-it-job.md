# პირველი სამსახური IT-ში: როგორ დაიწყო გამოცდილების გარეშე

„გამოცდილება გჭირდება სამსახურისთვის, სამსახური კი — გამოცდილებისთვის“ — ეს წრე IT-ში დამწყებთა უმეტესობამ იცის. კარგი ამბავი
ის არის, რომ IT-ში გამოცდილება ხშირად სამსახურამდეც შეიძლება დააგროვო: პროექტებით, სტაჟირებით, ღია კოდში მონაწილეობით და
ფრილანს-დავალებებით. ამ სტატიაში ნაბიჯ-ნაბიჯ განვიხილავთ, როგორ მიხვიდე პირველ შეთავაზებამდე.

> სტატია ზოგად რჩევებს შეიცავს. ბაზარი სწრაფად იცვლება — კონკრეტულ კომპანიებზე და ხელფასებზე ინფორმაცია ყოველთვის ახალი
> ვაკანსიებიდან და იმ სფეროში მომუშავე ადამიანებისგან გაარკვიე.

## 1. აირჩიე ერთი მიმართულება

„IT“ ძალიან ფართო სიტყვაა. პირველ ეტაპზე აირჩიე ერთი მიმართულება და მასზე გააკეთე ფოკუსი:

- **ფრონტენდ დეველოპმენტი** — ვებგვერდებისა და აპლიკაციების ის ნაწილი, რასაც მომხმარებელი ხედავს (HTML, CSS, JavaScript და ერთი
  ფრეიმვორკი).
- **ბექენდ დეველოპმენტი** — სერვერი, მონაცემთა ბაზები, API-ები (მაგალითად, Node.js, Python, Java, C#, Go).
- **QA / ტესტირება** — ხარისხის შემოწმება; ხშირად უფრო ადვილი შესასვლელია და შემდეგ ავტომატიზაციაზე გადასვლაც შეიძლება.
- **მონაცემთა ანალიტიკა** — SQL, Excel, ვიზუალიზაცია, საწყისი სტატისტიკა.
- **UI/UX დიზაინი, DevOps, კიბერუსაფრთხოება** და სხვა.

როგორ აირჩიო? ნახე საქართველოში გამოქვეყნებული ვაკანსიები რამდენიმე კვირის განმავლობაში: რომელ მიმართულებაზეა მოთხოვნა დამწყებ
დონეზე და რომელი მოთხოვნები მეორდება. შემდეგ სცადე თითოეულის საფუძვლები ერთი-ორი კვირით — ნახავ, რა გსიამოვნებს.

## 2. ისწავლე სისტემურად

სწავლის გზები ბევრია: უნივერსიტეტი, ფასიანი ბუთქემპები, უფასო ონლაინ კურსები და დოკუმენტაცია. მთავარი ის კი არაა, სად სწავლობ,
არამედ ის, რომ ისწავლილს **იყენებ პროექტებში**.

პრაქტიკული რჩევები:

1. შეადგინე გეგმა 3–6 თვეზე: რა თემები, რა თანმიმდევრობით, კვირაში რამდენი საათი.
2. ყოველი თემის შემდეგ გააკეთე პატარა პროექტი — არა მხოლოდ ვიდეოს ყურება.
3. ისწავლე Git და GitHub თავიდანვე — ეს ყველა მიმართულებაში გამოგადგება.
4. ისწავლე ოფიციალური დოკუმენტაციის კითხვა (მაგალითად, MDN ვებ-ტექნოლოგიებისთვის). ეს უნარი სამსახურში ყოველდღე დაგჭირდება.
5. ინგლისური გააუმჯობესე — დოკუმენტაცია, შეცდომების ძებნა და ბევრი საერთაშორისო კომპანია ინგლისურზეა.

ფასიან კურსზე ჩაწერამდე გაარკვიე: ვინ ასწავლის, რა პროექტებს აკეთებენ სტუდენტები, და ესაუბრე კურსდამთავრებულებს. „გარანტირებული
სამსახურის“ დაპირებას სიფრთხილით მოეკიდე.

## 3. შექმენი პორტფოლიო

დამსაქმებელს უნდა დაანახო, რომ **შეგიძლია**. 2–4 კარგად შესრულებული პროექტი ათ დაუმთავრებელზე ბევრად უკეთესია.

კარგი პროექტი:

- რეალურ პრობლემას წყვეტს (თუნდაც პატარას — შენთვის, მეგობრისთვის, ადგილობრივი ორგანიზაციისთვის);
- GitHub-ზეა სუფთა კოდით და README ფაილით, სადაც ახსნილია, რას აკეთებს და როგორ გაუშვა;
- თუ შესაძლებელია, ონლაინაა გაშვებული, რომ ნახვა ადვილი იყოს;
- აჩვენებს, რომ ფიქრობ ტესტებზე, შეცდომებზე და მომხმარებელზე.

## 4. CV და LinkedIn

- **ერთი გვერდი** საკმარისია დამწყებისთვის.
- თავში — რა მიმართულებით ეძებ სამსახურს და ძირითადი უნარები.
- პროექტები ბმულებით, და თითოეულზე ერთი-ორი წინადადება: რა გააკეთე და რა ტექნოლოგიით.
- წინა სამსახური (თუნდაც IT-ს გარეთ) — გამოყავი ის უნარები, რაც IT-შიც გამოგადგება: პასუხისმგებლობა, კომუნიკაცია, პრობლემების
  გადაწყვეტა.
- ყოველ ვაკანსიაზე CV ოდნავ მოარგე — გამოიყენე ის სიტყვები, რაც ვაკანსიაშია, თუ მართლა გაქვს ეს უნარი.

LinkedIn-ზე პროფილი CV-ს შეესაბამებოდეს. დაწერე, რას სწავლობ და რას აკეთებ — რეკრუტერები ხშირად იქ ეძებენ კანდიდატებს.

## 5. სტაჟირება და პირველი გამოცდილება

- **სტაჟირება და junior პროგრამები** — ბევრი კომპანია წლის გარკვეულ პერიოდში აცხადებს მიღებას. ადევნე თვალი კომპანიების
  გვერდებსა და ვაკანსიების საიტებს.
- **ღია კოდი (open source)** — პატარა გამოსწორებებიც კი რეალური გუნდური სამუშაოს გამოცდილებაა.
- **მოხალისეობა და პატარა ფრილანს-დავალებები** — ვებგვერდი არასამთავრობო ორგანიზაციისთვის ან ადგილობრივი ბიზნესისთვის.
- **ჰაკათონები და ღონისძიებები** — ხალხის გაცნობისა და გუნდში მუშაობის კარგი შესაძლებლობა. ინფორმაცია ღონისძიებებზე და
  პროგრამებზე ხშირად საქართველოს ინოვაციებისა და ტექნოლოგიების სააგენტოს (GITA) გვერდზეც ქვეყნდება.

## 6. გასაუბრება

IT გასაუბრება ჩვეულებრივ რამდენიმე ეტაპიანია: HR საუბარი, ტექნიკური კითხვები, ზოგჯერ სახლში შესასრულებელი დავალება ან პირდაპირ
კოდის წერა. მოემზადე ასე:

- გაიმეორე შენი მიმართულების საფუძვლები და იცოდე, რატომ გააკეთე ესა თუ ის გადაწყვეტილება შენს პროექტებში;
- ხმამაღლა იფიქრე დავალების ამოხსნისას — ხშირად უფრო მნიშვნელოვანია, როგორ ფიქრობ, ვიდრე სრულყოფილი პასუხი;
- თუ რაღაც არ იცი, თქვი პირდაპირ და აჩვენე, როგორ გაარკვევდი;
- მოამზადე კითხვები კომპანიისთვის: როგორ მუშაობს გუნდი, ვინ დაგეხმარება პირველ თვეებში, როგორ ხდება სწავლა.

ყოველი უარის შემდეგ, თუ შესაძლებელია, ჰკითხე უკუკავშირი. უარი ნორმალური ნაწილია — ბევრ დამწყებს პირველ შეთავაზებამდე ბევრი
განაცხადის გაგზავნა უწევს.

## სავარაუდო გეგმა

| პერიოდი | რა გააკეთო |
|---|---|
| 1-ლი თვე | მიმართულების არჩევა, ვაკანსიების ანალიზი, სწავლის გეგმა, Git |
| 2–4 თვე | სისტემური სწავლა, 2–3 პროექტი, GitHub პროფილი |
| 4–5 თვე | CV, LinkedIn, პირველი განაცხადები, სტაჟირებები, ღონისძიებები |
| 5+ თვე | გასაუბრებები, უკუკავშირით გაუმჯობესება, ახალი პროექტი |

ეს ვადები ორიენტირია — ყველაფერი დამოკიდებულია იმაზე, კვირაში რამდენ დროს უთმობ და საიდან იწყებ.

## ხშირი შეცდომები

- **ყველაფრის ერთად სწავლა** — სამი ენა და ხუთი ფრეიმვორკი ზედაპირულად ნაკლებად გამოგადგება, ვიდრე ერთი მიმართულება კარგად.
- **„tutorial hell“** — გაუთავებელი კურსები საკუთარი პროექტების გარეშე.
- **განაცხადის გადადება „სანამ მზად ვიქნები“** — სრულად მზად არასდროს იქნები; ადრე დაიწყე და გასაუბრებებიდან ისწავლე.
- **ერთი და იგივე CV ყველგან** — მცირედი მორგება შედეგს ცვლის.

## სასარგებლო ბმულები

- საქართველოს ინოვაციებისა და ტექნოლოგიების სააგენტო (GITA): https://gita.gov.ge
- MDN Web Docs (ვებ-ტექნოლოგიების დოკუმენტაცია): https://developer.mozilla.org
- Git-ის ოფიციალური დოკუმენტაცია: https://git-scm.com/doc
- GitHub Docs: https://docs.github.com
